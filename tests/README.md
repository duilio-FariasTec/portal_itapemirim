# Testes do ANI

Planejar testes somente após regras e contratos serem especificados. A estratégia candidata inclui testes unitários de domínio/aplicação, testes de integração da API e persistência e testes de autorização positiva e negativa. Fluxos críticos de portais e requisitos de carga/segurança dependem do risco e dos responsáveis.

Use dados sintéticos e ambientes/dependências controlados; nunca use dados reais de clientes, cartões, credenciais ou informações pessoais. Não conecte testes a serviços reais nem a bancos compartilhados sem autorização e configuração de ambiente explícita.

Os comandos dependem do repositório e das soluções que forem criadas; não há comandos de teste presumidos neste espaço. Relate exatamente quais verificações foram executadas e seus resultados.
